# GameDesk

GameDesk — демонстрационная панель управления каталогом игр. Здесь можно посмотреть статистику каталога, найти игру, создать запись, отредактировать её или удалить. Интерфейс и API работают с отдельным набором данных для каждого посетителя.

## От учебного проекта к портфолио

Исходный репозиторий содержал Express-сервер, JSON-файл с одной записью, статическую страницу с карточками, форму добавления и удаление. Запуск через `npm start` был сломан: команда указывала на отсутствующий `index.js`, хотя сервер находился в `app.js`. В Git также попал `node_modules`. Старая страница удаляла карточку до подтверждения от сервера, не различала ошибки добавления и могла обращаться к отсутствующему ответу после сетевого сбоя. Неизвестный ID при удалении приводил к ошибке сервера. Эти места заменены рабочим CRUD и единым форматом ошибок.

При доработке добавлены Vue-интерфейс, страницы обзора и игры, редактирование, валидация, поиск и фильтры на сервере, пагинация, SQLite, отдельные демонстрационные сессии, адаптивная вёрстка, проверки API и клиентской логики. Исходная запись сохранена в `data/games.json`: при создании каждой сессии поля `image` и `link` преобразуются в `imageUrl` и `gameUrl`, а запись переносится вместе с 17 новыми демонстрационными играми. Её исходное описание дополнено пометкой, чтобы удовлетворять новым правилам длины. Исходный JSON не перезаписывается.

## Возможности

- Обзор: общее число игр, опубликованные записи, черновики, жанры и последние добавленные игры. Все числа вычисляются из текущей сессии; это демонстрационные данные, не статистика пользователей.
- Каталог: поиск по названию с удалением лишних пробелов и сравнением без учёта регистра, фильтры по жанру, платформе и статусу, сортировка и страницы по 5, 10 или 20 записей. Параметры хранятся в URL. Устаревшие ответы поиска отменяются.
- Создание, просмотр, редактирование и удаление с подтверждением. При сбое удаления строка остаётся в списке.
- Общая форма создания и редактирования: подсказки возле полей, перевод фокуса к первой ошибке, предпросмотр обложки, предупреждение о несохранённых изменениях, запрет повторной отправки.
- Индивидуальный демонстрационный каталог посетителя и кнопка восстановления исходного набора.

## Стек и требования

Node.js 20+, npm 10+, Vue 3 (`<script setup>`, Composition API), Vue Router, Vite, JavaScript ES Modules на клиенте, SCSS, Fetch API, Express, SQLite через `better-sqlite3`, Vitest, Node Test Runner и Supertest. Для локального запуска SQLite устанавливается через npm; при установке на VPS может понадобиться компилятор C++ и Python для нативного модуля.

## Запуск

```bash
git clone https://github.com/dyakovmaksim/games-rating-admin.git
cd games-rating-admin
npm ci
cp .env.example .env
npm run dev
```

Клиент доступен на `http://localhost:5173`, API — на `http://127.0.0.1:3000`. Vite проксирует `/api` на Express. `npm start` запускает только сервер; после `npm run build` он также раздаёт собранный клиент на порту 3000. Проверки: `npm test`; production-сборка: `npm run build`.

Пример переменных находится в [.env.example](.env.example): `PORT`, `HOST`, `DATABASE_PATH`, `CLIENT_ORIGIN`, `SESSION_DAYS`, `COOKIE_SECURE`. В рабочей среде укажите абсолютный путь к базе вне каталога сборки. Для HTTPS поставьте `COOKIE_SECURE=true`. `.env`, SQLite-файлы и `dist` не попадают в Git.

## Данные и устройство проекта

При первом запросе посетителя сервер создаёт анонимную сессию, копирует в неё 18 исходных записей и сохраняет ID в непрозрачном `HttpOnly` cookie. Срок бездействия по умолчанию — семь дней; просроченные сессии удаляются при ближайшем запросе после часа с последней очистки. После восстановления набор создаётся заново только для текущей сессии. Лимиты: 50 игр на сессию, тело запроса до 16 КБ и минимум 750 мс между изменяющими запросами одной сессии. Это публичная демонстрация, а не защищённая админка: настоящей авторизации и ролей нет.

`client/src/pages` содержит страницы, `components` — переиспользуемые части интерфейса, `services/api` — запросы, `utils` — валидацию, `composables` — уведомления, `styles` — SCSS. На сервере `routes` задают адреса, `controllers` формируют HTTP-ответы, `services` проверяют правила, `repositories` выполняют SQL, `validation` проверяет входные данные, `middleware` создаёт сессию и ограничивает изменения, `database` хранит схему и импорт. Такое разделение позволяет менять интерфейс, не переписывая SQL, и тестировать правила отдельно от отображения.

Схема находится в `server/database/schema.sql`. При первом запуске SQLite создаёт таблицы и индексы. `server/database/seed.js` читает `data/games.json`, преобразует старые имена полей и добавляет демонстрационные записи. Чтобы начать с пустой рабочей базы, удалите локальный `.sqlite`-файл при остановленном сервере; новые сессии затем получат исходный набор автоматически. Уже созданные сессии можно восстановить кнопкой в интерфейсе.

## API

| Метод | Адрес | Назначение |
| --- | --- | --- |
| GET | `/api/health` | Проверка доступности |
| GET | `/api/stats` | Статистика текущей сессии и значения фильтров |
| GET | `/api/games` | Список и `pagination` |
| GET | `/api/games/:id` | Одна игра |
| POST | `/api/games` | Создание |
| PATCH | `/api/games/:id` | Изменение |
| DELETE | `/api/games/:id` | Удаление |
| POST | `/api/demo/reset` | Восстановление демонстрационного набора |

Список принимает `search`, `genre`, `platform`, `status`, `sort`, `page`, `limit`. Сортировки: `newest`, `oldest`, `title`, `releaseNewest`, `releaseOldest`. Ошибки возвращаются как `{ "error": { "code": "...", "message": "...", "details": {} } }`; поле `details` присутствует у ошибок валидации.

## Изображения

Новые демонстрационные записи используют CSS-обложки с названием игры: внешние изображения не копируются и не требуют лицензий. В исходной учебной записи сохранён старый URL изображения (`http://localhost:3000/`); если он недоступен, интерфейс показывает ту же типографическую обложку. Ссылки на игры в демонстрационном наборе ведут на поиск по названию на IGDB и служат примерами внешних ссылок, а не подтверждением данных об игре. Шрифт Manrope загружается через Google Fonts; при недоступности используется Arial.

## Публикация и обновление

Рабочая демонстрация: [http://193.233.126.148:8088](http://193.233.126.148:8088). Порты 80 и 443 заняты другим сайтом, поэтому GameDesk работает на отдельном порту 8088 без HTTPS. Backend запущен как `gamedesk.service` на `127.0.0.1:3188`, отдельный `gamedesk-nginx.service` раздаёт `dist` и проксирует `/api`. База хранится в `/var/lib/gamedesk/catalog.sqlite` вне директории сборки.

Примеры конфигурации лежат в `deploy/`. Для новой установки нужны Node.js 20+, Nginx, каталог `/srv/gamedesk` и отдельный каталог `/var/lib/gamedesk` с правом записи для пользователя сервиса. Сборку выполняйте в исходном репозитории, затем перенесите файлы в `/srv/gamedesk` без `.git`, `node_modules`, `.env` и рабочих баз:

```bash
npm ci
npm run build
rsync -a --exclude='.git/' --exclude='node_modules/' --exclude='.env' --exclude='*.sqlite*' ./ /srv/gamedesk/
cd /srv/gamedesk && npm ci --omit=dev
```

Создайте `/etc/gamedesk.env` по [.env.example](.env.example), указав `PORT=3188`, `HOST=127.0.0.1`, `DATABASE_PATH=/var/lib/gamedesk/catalog.sqlite`, `CLIENT_ORIGIN=http://ваш-адрес:8088` и `COOKIE_SECURE=false` для HTTP. Установите [systemd-сервис API](deploy/gamedesk.service.example), [конфигурацию Nginx](deploy/nginx.conf.example) и [отдельный сервис Nginx](deploy/gamedesk-nginx.service.example), предварительно проверив пути и свободный порт. Включите сервисы через `systemctl daemon-reload` и `systemctl enable --now`. Не запускайте обычный системный Nginx на 80/443, если эти порты уже заняты. При появлении отдельного домена настройте HTTPS и `COOKIE_SECURE=true`.

При обновлении повторите сборку, `rsync` и `npm ci --omit=dev`, затем `systemctl restart gamedesk.service`; Nginx увидит новый `dist` без перезапуска. Перед обновлением сохраните копию SQLite-файла. Проверьте `/api/health`, прямой переход на `/games`, создание записи и её сохранение после перезапуска backend.

## Ограничения

Демонстрационные игры и даты в наборе служат проверке интерфейса; внешние ссылки могут измениться. Реальной авторизации нет. Текущая публикация по IP и порту 8088 работает без HTTPS, поэтому её нельзя использовать для личных данных. Ограничение частоты действует на одну анонимную сессию и не заменяет защиту публичного сервиса на уровне Nginx. Поиск и фильтры выполняются в SQLite; при большом каталоге понадобится отдельная стратегия индексирования текста. Исходная учебная запись содержит ссылку на `localhost` и нуждается в ручном обновлении для реального каталога.
